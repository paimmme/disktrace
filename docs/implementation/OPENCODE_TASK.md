# 交给 OpenCode 的执行指令

请在 `$HOME/Documents/DiskTrace` 中执行本任务。

首先完整阅读：

1. 所有适用的 AGENTS.md。
2. `docs/implementation/OPENCODE_IMPLEMENTATION_SPEC.md`（本任务的详细实施与验收合同）。
3. `docs/PRODUCT_STATUS.md`、`docs/DiskTrace_PRD_v4.0.md`、`docs/ARCHITECTURE.md`。

核心目标是：用户磁盘空间很少，Code Agent 自动任务下载依赖、生成产物和留下文件，导致清理后又快速变满。软件必须告诉用户空间何时减少、增长在哪些目录和具体文件、是否与某次任务有可核验关联、哪些文件在任务后仍存在，并能持续运行和及时提醒。

同目录的 `SOURCE_BASELINE.json` 记录现有源码摘要，`DOCUMENT_VALIDATION.json` 仅记录文档 SQL/JSON 校验，不是实现验收。当前代码有未提交的 UI/只读连接/测试改动，必须保留。不要 reset、清理工作区、覆盖用户历史、修改 Codex 日志或配置。先保存工作区基线和运行现有测试，再按规格 M0–M8 实施。

请直接实施代码、migration、测试、打包和真机验证，不再提交一份泛化计划，也不重新做需求问卷。已确定的默认值、数据结构、算法边界、测试矩阵和完成条件都在规格中。实现细节可以自行处理，产品边界不得擅自改变。

必须特别防止：

- 只凭时间/工作目录重合就宣称确认 Agent 写入。
- 将父子目录变化累加，或为了去重把项目子目录证据过滤掉。
- 长日志读到预算就永久停住，半行跨重启丢失。
- 用 0 冒充未知文件前值，把权限恢复当新增。
- 监控工具自己无界增加索引、日志或占用空间。
- 系统通知只在窗口打开时有效。

不自动删除用户文件，不读取文件正文，不保存提示词/命令/工具载荷，不创建额外常驻服务或云端组件。只读元数据不等于可以读取认证信息。

系统权限、真实退出登录/重启、真实运行 24 小时等不能用模拟代替；需要用户执行时给出已经准备好的具体操作，并把相应验收项标 NOT RUN/BLOCKED。继续完成其他不依赖该操作的工作，不虚报 PASS。

完成时交付代码、可运行本地 App、启停和回退说明，以及 `docs/ORIGINAL_NEED_ACCEPTANCE.md` 的逐项证据矩阵。明确区分工程测试通过、本机功能通过、指定 Codex 客户端通过、登录恢复通过和正式发布未完成。
