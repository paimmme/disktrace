# DiskTrace 本轮修复执行文档

日期：2026-10-13。基线：2191371。目标：修复复查中真实缺陷，把“空间何时减少、哪些文件变化、原因有多可信”变成可持续使用的功能。保留现有中文 UI、用户数据和观察历史。

## 实施范围与顺序

1. 先将上轮三项失败回归纳入正式测试：未验证目录不能通知；恢复/宽扫描窗口不能升级；重复事件不能丢文件、净值与用户确认。
2. 统一归因入口：目录不独立发送 Agent 通知；事件严格要求 liveHintWindow、可靠测量、完整已验证唯一任务；无 live 路径证据时明确未知，不能为了提醒而降低标准。
3. 事件合并：真实 UPSERT；事件文件关系累积；从全部关联事实重算净值；用户反馈优先；重算保持 created_at。
4. 加上总库存字节/行数与总自身占用保护，预算包括旧有效代次和准备代次。预算不足终止准备扫描、保留有效基线并显示 quotaLimited，不能先删历史腾空间。
5. 把容量循环从扫描中独立出来；所有入口共用运行器、写者锁和普通执行上下文的信号取消。加心跳，慢扫描不阻止采样。
6. 建立本地文件命令和回执：确认/撤销、暂停/恢复、手动校准、通知授权。UI 不写历史库，命令经过路径/owner/大小/版本/有效期校验。
7. 接通 ServiceManagement 注册状态与通知授权操作。授权必须由用户点击；不自动更改通知或登录偏好。通知缺少值时不显示虚假 0。
8. 安全打包：仅清理本次创建的 staging；校验 .app 输出、拒绝危险路径和 symlink；成功核验后保留旧包再替换，不能 rm -rf 用户指定目录。
9. 修复 unknown 显示和文件/事件分页；详情缺失明确报错，不用空数组冒充没有变化。
10. 隔离验收通过后，先停止现有旧写者，SQLite backup API 备份真实历史，再更新本地包和后台，验证新表、真实文件记录与连续容量采样。不得把新旧写者同时运行。

## 测试与交付门槛

- 原 99 项测试持续通过；新增针对性回归覆盖上述行为，不修改测试来接受误归因。
- 三项旧失败回归必须通过，事件更新后两文件保留、净值正确、确认未丢。
- 小字节预算、两个入口抢同一 DB、120 秒慢扫描（使用可控测试阻塞）、命令重复/过期/符号链接、分页同时间边界有确定性测试。
- 本机先在临时目录/数据库测试新增、增长、删除与重启，避免写大量测试数据。
- 本地部署保留备份与旧 App，真实 DB 迁移后旧版本不可直接写入。
- 通知横幅、登录恢复、真实客户端认证等未经过用户操作验证的项目分别标 NOT RUN，不把原生 API 存在当通过。
- 交付修复代码、本地可运行版本、测试输出、更新验收说明和回退位置。没有自动清理用户文件、没有自动推送。

## 对原始需求的边界

文件净变化是观测事实，任务关联是证据推断。下载类型、文件夹名、时间重合都不能证明写入者。范围外缓存、APFS 共享块和缺少前值继续保持未知；软件必须允许用户看到具体路径、时间和限制。真实客户端未验证时不发送 Agent 归因通知，但空间不足提醒及文件变化记录必须可用。
