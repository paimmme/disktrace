# DiskTrace — 产品需求与验收规格 PRD v4.0

> **状态**：产品范围冻结；供工程开发与验收使用，未宣称已实现。  
> **基准**：`DiskTrace_Technical_Architecture_Review_v4.0.md`（技术实现的最高优先依据）；替代旧版 `DiskTrace_PRD_v3.2.md`。  
> **项目定位**：Local-first、macOS 14+、MIT 开源、聚焦 AI Coding Agent 自主任务写盘的长期磁盘空间溯源工具。

## 0. 文档优先级、交付原则

- 产品目标、交互、分类规则与验收标准以**本 PRD**为准；扫描技术、上游复用与模块划分以**技术架构 v4.0**为准。冲突需记录为 ADR，优先不改变用户已确认的功能边界。
- 不拆分人为的四阶段 PR；允许内部逐步提交、自动测试、开发前技术闸门。一次性交付不代表跳过验证。
- **Engineering Complete**（功能与自动化证据交付）≠ **Release Ready**（真实 macOS 安装、权限、硬件与持续运行关键验收全部通过）。
- 所有外部组件和 macOS 权限能力须在开发环境验证，不允许把“计划实现”写成“已实现”。

## 1. 用户问题与产品目标

### 1.1 核心问题

磁盘空间被逐步耗尽，却无法知道哪次 Codex / Claude Code 等 Agent 任务下载依赖、缓存模型、生成编译输出或遗留临时文件。现有磁盘清理工具擅长识别**当前大文件**，缺少**何时增加、与哪个 Agent 相关、证据是否可靠**的持续历史。

### 1.2 一句话价值

**知道 Mac 的磁盘空间何时变化、增长在哪里、是否与 AI Agent 任务有关；对普通预期操作尽量不打扰。**

### 1.3 首版目标

- 用户无需保持主界面打开，也能长期记录卷级空间趋势与可访问目录的变化。
- 发生有证据支持的 AI Agent 异常增长时，优先提醒并展示证据链；无法归因时不冒充已确认。
- 用户普通下载、Finder 复制/移动等行为保留在历史中，默认不发“AI Agent 异常增长”通知；低空间安全提醒独立。
- 支持时间线下钻、目录增长对照、Finder 定位与经确认的手动清理、健康度/权限可见、隐私优先。
- 尽最大可能复用成熟开源代码，不构建另一套扫描器、文件树图形引擎、更新器或进程服务平台。

### 1.4 非目标

不做系统安全审计、100% syscall 日志、全量进程精确字节归属、自动删除、端云同步、Windows/Linux、Agent 文本内容分析、通用 AI 用户意图模型、永久高权限后台监控。

## 2. 用户角色和主要场景

1. **AI 编程开发者（首要）**：使用 Codex 生成代码和环境依赖；第二天看到 10GB 额外占用，追溯到时间、路径及关联任务；得知证据与不确定性。
2. **多 Agent 开发者**：同时使用 Codex 与 Claude Code；即使 Claude Code 尚无首版官方任务级适配，也能观察目录/进程证据，不能捏造任务关联。
3. **普通 Mac 用户（次要）**：查看整体空间变化、了解磁盘增长；普通下载/复制默认静默，空间接近耗尽时中性提醒。
4. **开源维护者**：通过健康度视图与可脱敏诊断材料定位权限、事件丢失、扫描差异、数据库迁移问题。

## 4. 首版交付范围（P0）

### P0-1：长期监控与校准

- 用户级 Agent 登录后可独立运行，关闭主窗口不停止采集；明确暂停、恢复与完全停止。
- 卷级空间采样（包括采样时间、卷标识、可用空间口径）和 FSEvents 的变化线索；去抖、事件合并、有界队列与校准调度。
- 初次启动无需等待完整扫描；未经校准区域标记 `pending_baseline`。
- 使用一个扫描后端；优先接入 RadixCore，定期及按需增量复扫；不可用时回退、标记缺口。
- 受监控目录增减和卷级可用空间变化分别展示；APFS 快照、克隆、hard link、不可访问目录等可能造成差异，不强行相加。

### P0-2：历史溯源

- 时间线：卷级可用空间趋势、时间范围、明显增长窗口与原因概览。
- 目录变化：Top N、路径、时间、占用口径、扫描时间、覆盖状态；支持选择时间窗口。
- 归因详情：目录归属、实际观测进程、父进程（有证据才展示）、Codex 活动关联、证据来源/时间/局限、未解释差额。
- 多版本证据补充不能覆盖原始观测事实；归因置信度与数据校准状态是两套独立概念。

### P0-3：Agent-first 告警过滤

观察、证据、通知判定必须分离：

- `Observation`：卷级采样、目录净变化、事件线索；**任何静默规则不得删除这些历史**。
- `Evidence`：路径规则、进程操作证据、已验证的 Agent 任务事件、用户明确反馈；记录来源和局限。
- `AlertDecision`：通知/静默、原因、证据等级、规则版本、阈值、冷却、时间戳。

| 场景 | 首版默认行为 | 关键限制 |
|---|---|---|
| 明确或有较强线索的普通用户下载、Finder 复制 | 记录并静默 Agent 通知 | 不自动宣称全部为“用户确认”；目录名不足以证明用户意图 |
| 确认的 Codex 活动 + 路径级证据 + 增长阈值 | 发 Agent 相关异常通知 | 只有时间重叠时不允许归因为已确认 |
| Codex 活跃 + 大量 `node_modules` 变化，无进程/任务关联路径证据 | 记录，默认静默 | 不能声称 Codex 写入了全部增长 |
| 同时发生浏览器下载与 Agent 构建 | 分别记可证实变化，不可分部分保留未知 | 禁止把整个窗口净增长归给 Agent |
| 未知来源空间下降 | 记录、标记待查 | 仅在严重低空间/用户自定义全局条件时发中性安全提醒 |
| 触及危险低空间阈值 | 独立中性安全提醒 | 不论产生原因，不能误指向 Agent |

- 告警支持阈值、合并、冷却、免打扰；用户可以“这是我主动操作”“持续关注该来源”“撤销规则”。
- 用户确认仅适用于其明确反馈的事件或规则作用域。规则本地存储、可解释、可撤销。
- 宁可少报证据不足的 Agent 行为，也不得误报普通下载为已确认 Agent 写盘。

### P0-4：Codex 集成与可选深追

- 首发为 **Codex**，用户授权范围内优先读取可验证的非内容元数据：会话标识（必要时哈希）、活动时间、工作目录、客户端种类。
- 增强通知/事件接口在实际客户端验证后才提供“一键集成”；追加式配置、先备份和校验、可撤销。不截获提示词、任务正文、代码或原始命令行。
- Codex CLI、IDE、Desktop 的覆盖范围分别标示；`notify` 不等于适用于所有客户端的完整任务流。
- Deep Trace：真实进程级文件活动观测只在用户授权后限时运行；记录可证明的 PID/路径/时间，权限不可用时明确降级。不得采用虚构追踪或把时间关联冒充实际 PID 证据。
- Claude Code 进入未来适配清单；首版可保留接口和常规进程/目录归属，但不要求首版完成 Claude Code 专用 Hooks。不能为满足“多 Agent”而伪造数据。

### P0-5：UI、手动操作与健康度

- SwiftUI 主界面 + Swift Charts 时间线；异常详情下钻；可选按需打开 Radix 的树图/旭日图（不常驻整树）。
- 健康度：Agent 状态、卷采样时间、基线进度、最近目录校准、覆盖及权限缺口、事件丢失、历史存储预算和警报策略。
- Finder Reveal；移至废纸篓前重新检查文件路径、权限、符号链接及危险目录，并经过用户确认；不强制删除运行中的应用数据库、容器卷或系统文件。
- 设置：监控根目录/排除目录、数据配额与保留时间、通知过滤、Codex 集成、深追授权、更新检查、历史清空和导出前脱敏。

### P0-6：故障、隐私和安装

- 休眠/重启/Agent 异常终止后尝试从可用事件检查点恢复，必要时限量重扫；无法恢复的操作保留 `CoverageGap`。
- SQLite 单写入方、事务迁移、WAL 与快照同计入配额；旧历史损坏不得被自动覆盖；超额先汇总/删除可重建数据。
- 不采集文件内部内容、不上传监控元数据、限制数据库权限；更新检查联网需告知，不发送用户路径或会话记录。
- GitHub Releases 签名与公证（取决于证书可用性）、双架构构建、图形化注册/卸载用户级 Agent；更新由用户确认。

## 5. UX / 信息架构

1. **Home — History**：剩余空间曲线 + 区间选择 + Agent 相关增长事件 + 来源未知窗口 + 最近通知。
2. **Growth Details**：目录净增、测量口径、实测/推断标签、时间与关联任务、为何提醒或为何静默。
3. **Deep Dive**：选定目录后才实例化完整文件树/旭日图/矩形树图；可跳转 Finder 和谨慎手动清理。
4. **Monitoring Health**：监控可用性、扫描时效、权限、Gap、低资源模式与本地数据库健康。
5. **Settings**：权限、范围、保留策略、Agent 配置、警报阈值、更新和隐私控制。

### 关键状态文案

- `Baseline pending` / 「正在建立基线」；`Calibrated at ...` / 「已于 … 校准」；`Coverage gap` / 「该时段有监控缺口」。
- `Agent-related, inferred` / 「可能与 Agent 活动有关」；`Observed process write` / 「已观测到进程写入操作」；`Unknown source` / 「来源未知」。
- `No alert — expected activity evidence` / 「已静默：有预期操作线索」；`Safety alert — low space` / 「磁盘剩余空间不足」。

不要以一个 0–100 的“准确率/信任分”替代具体证据说明；更不要展示无依据的“Agent 导致 +5GB”。

## 6. 技术与开源复用不可变约束

- 遵循 `DiskTrace_Technical_Architecture_Review_v4.0.md` 的 ADR-01 至 ADR-09：**一个用户级 Agent、一个 App、一个 SQLite、一套扫描后端、少量按需适配器**。
- 首选经真实验证的 RadixCore Swift Package；OpenDisk 只作 benchmark/备选后端；agentflash 借鉴事件关联和 Hooks 设计，不纳入 Go/HTTP/WebSocket 常驻服务。
- 公共 API、MainActor 隔离、内存释放、macOS 14 兼容、Swift 工具链及版权许可证必须先做验证；失败可做最小 vendor / 适配，不直接重写整个扫描器。
- 不新建独立 Investigation Engine、常驻 watchdog、全盘 syscall 服务、自动 AI 意图模型、自研 updater、长期保存每次完整文件树。

## 7. 性能和默认参数（待实测，不作预先承诺）

| 指标 | 产品目标 / 默认建议 | 实测方式 |
|---|---|---|
| Agent 空闲 CPU | 平均 <0.5% | 空闲 30 分钟，报告系统版本、机器、采样频率和计算方式 |
| Agent 常驻内存 | <50MB | 记录 RSS 或物理占用口径；与 UI、按需扫描 worker 区分 |
| 卷级异常初步发现 | 约 1 分钟 | 正常唤醒且有权限时，注入可控占用变化测试 |
| 卷级采样周期 | 建议 60 秒 | 用户可配置，异常时可短暂增加频率 |
| 细粒度 / 小时 / 日汇总 | 建议 7 / 90 / >90 天 | 以软配额优先，展示实际保留范围 |
| 本地数据库总占用 | 建议默认 1GB 软配额 | 包括 SQLite、WAL、索引、快照、缓存和临时文件 |

## 8. 发布验收矩阵

| ID | 必须验证 | PASS 判据及约束 |
|---|---|---|
| T01 | 首次启动及后台运行 | App 关闭后 Agent 仍采样；退出/暂停动作语义正确；渐进基线无虚假新增 |
| T02 | 文件新增、删除、移动、硬链接/克隆 | 目录净增与校准口径一致，无法精确对账时可解释且标记差额 |
| T03 | Finder/浏览器用户操作 | 卷与目录变化入库；无误导 Agent 告警；不能凭目录硬判用户确认 |
| T04 | 有证据的 Codex 任务增长 | 符合阈值时提示，列出证据与限制；仅在已验证客户端宣称任务关联 |
| T05 | 并发用户 + Agent 活动 | 无法区分的增长保持 unknown，不把全部增长归给 Agent |
| T06 | 深度追踪 | 用户授权后限时实际观测；拒绝/失败仍正常监控，未授权时不运行 |
| T07 | 大规模文件事件压力 | 去重、队列上限、冷却和缺口标记生效；无无限内存或 CPU 风暴 |
| T08 | 休眠/中断与自愈 | 恢复采样；记录 Gap；受损库不被静默重建覆盖 |
| T09 | 告警过滤 | 预期操作默认静默、低空间中性提醒、可解释规则版本和用户撤销 |
| T10 | 隐私 | 敏感 prompt/command/secret 不入库不入日志，导出脱敏、数据库权限正确 |
| T11 | 空闲性能与保留配额 | 记录 30 分钟测量，达标才标 PASS；大扫描峰值另行报告 |
| T12 | 分发、更新、双架构 | 验证安装、Agent 注册、升级、卸载、历史迁移；Intel/macOS14 与签名公证实际核验 |
| T13 | 健康度与手动清理 | 状态准确；Finder 定位、风险检查、确认与废纸篓操作真实有效 |

每项列出 `PASS / FAIL / NOT RUN / BLOCKED`、运行环境、命令/步骤、证据路径和限制。任何 `NOT RUN` 不得写为通过；T04、T06 等 Q20 核心能力缺失不能宣布完整首版。真实 Mac 关键项未通过不得 `Release Ready`。

## 10. 实施终点

按本 PRD 交付**真实可执行的软件工程、构建/测试证据和真实 Mac 验收说明**。不再开展重复产品问卷，也不开始新一轮 PR 拆分。若架构风险无解，给出最小可验证替代与准确的未完成说明，而不是捏造已实现能力。
