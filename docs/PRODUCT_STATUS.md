# DiskTrace：原始目标与当前实现对照

评估日期：2026-10-13；基于 2191371 后本地修复。执行文档：`implementation/REPAIR_EXECUTION_2191371.md`。

## 结论

**可用于观察空间和查找监控目录内的具体文件变化，尚未完整实现“可靠解释是哪次 Agent 任务造成占用”的最初目标。** 扫描窗口与工作目录重合不等于写入证据。不能因为界面、测试或任务解析存在，就宣称原始需求已全部闭环。

| 原始问题 | 当前能力 | 限制 |
|---|---|---|
| 空间何时减少？ | 卷级容量历史、独立容量循环 | 默认 60 秒采样；睡眠/停止期间不能恢复精确时间。 |
| 哪些文件占了空间？ | 扫描库存差分、前后分配字节、文件明细、Finder 定位 | 默认 15 分钟校准；首次基线前的增长未知。监控范围外无文件事实。 |
| 变化属于什么类型？ | 依赖、构建、模型缓存、会话产物等路径分类 | 类型是路径提示，不是来源证明。 |
| 是哪次 Agent 任务写入？ | 会话任务元数据和候选展示；保守归因 | **未完成真实客户端验证；持久事件线索尚未接入即时逐路径差分。常规扫描保持 unknown。** |
| 任务后文件是否还在？ | 对合格候选计划 +10 分钟/+24 小时存在检查 | 缺乏合格实时关联时不会计划；真实 24 小时未验收。 |
| 快满时提醒？ | 容量安全策略、持久 outbox、原生授权与测试入口 | 真实系统横幅需用户授权并验证。不能把 acceptedByOS 当用户看到了。 |
| 日常运行是否可信？ | 同库单写者、心跳、独立采样、暂停/恢复回执、配额保护 | 登录恢复、长时间 CPU/RSS、电源恢复未验收；大目录可能 quotaLimited。 |
| 用户能直接查看和操作？ | 中文事件/文件界面、分页、未知值、确认/撤销和后台回执 | UI 只读历史，通过本地命令向后台提交操作；不自动清理文件。 |

## 本轮修复

- 恢复/宽扫描和未验证目录不再发送 Agent 归因提醒。
- 事件增量更新累积文件、重算净变化、保留用户确认，不再级联删除已有详情。
- 库存行数/估算字节预算覆盖各 root 与 active/preparing 代次；保护自身数据库/WAL/命令/日志/备份占用。预算保护不是 SQLite 文件字节数绝不超线的保证，事务和索引存在开销。
- CLI 与原生 Agent 共用写者锁和运行器；采样、扫描、命令分开运行；扫描异常会清理准备代次。
- 用户确认从无操作按钮变成命令回执；提供暂停/恢复/校准、通知授权/测试、登录服务注册状态。
- 安全打包保留旧 App，拒绝任意目录与符号链接输出；未知值不显示为零，同时间事件分页不跳过。
