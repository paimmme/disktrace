# 个人开发者视角：够用的边界与还差什么

面向：像 paimun 一样主要用 Codex/Claude 做项目、想搞清「磁盘怎么少的」的**个人**用户。不追求企业级完美。

## 已经够用的地方

- **卷级时间线**：回答「什么时候变紧的」。
- **监控目录 + 缓存根**：Codex 更新缓存 vs 会话目录可以分开看（时段条形图）。
- **保守归因**：时间重合不会变成「确认是某次任务写的」——对个人用户这是优点，避免误删文件。
- **本机 Codex Desktop 一条线**：`0.162.0-alpha.17.2` 已 `realClientVerified`（元数据解析），够支撑「任务候选」展示，不是写入证明。

## 对个人用户仍值得补、但不必一次做完

| 优先级 | 缺口 | 够用标准 |
|---|---|---|
| 高 | **首屏可读性** | 结论一句话 + 图，表格进折叠（本轮 UI 在改） |
| 高 | **监控范围在 App 里可勾选** | 不必手改 `local-run.json` |
| 中 | **macOS 通知** | 低空间时弹一次即可，不必 24h 压测 |
| 中 | **Claude Code 适配** | 有会话日志结构再验，没有就不宣称 |
| 低 | 公证 / Intel / 登录项自动恢复 | 开源 + 本机 ad-hoc 签名可先发布 |
| 低 | 「确认是哪次任务写入」 | 需要进程级证据；个人版可长期保持「候选 + 未知」 |

## GitHub 开源时别人会期待什么

- 清晰的 **README：能/不能做什么**（已有 `PRODUCT_STATUS.md`，保持诚实）。
- **一键构建说明**（`toolchain-env.sh` + `deploy-interval-slice.sh`）。
- **LICENSE**、不含本机 DB 的 `.gitignore`。
- Issue 模板可选；不必有 CI 矩阵，有 `swift test` 说明即可。

## 不必做

- 全盘扫描、自动清理、云同步。
- 100% 解释磁盘（APFS/未监控目录注定有差额）。
- 为过审而抬高归因强度。
